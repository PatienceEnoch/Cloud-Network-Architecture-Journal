# Design Principles

Reusable ideas I want to carry from one architecture to the next.

Current themes:

- reduce shared failure domains
- minimize unnecessary state
- isolate blast radius
- design for graceful degradation
- verify behavior after change
- prefer narrow authority over unrestricted automation
- make recovery paths explicit
