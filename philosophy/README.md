# Engineering Principles

Short ideas that help me reason about systems.

A few that keep showing up in my work:

> A backup path is architecture. Recovery time is behavior.

> Metrics tell me that something happened. Evidence helps explain why.

> A successful command is not proof of successful recovery.

> Observability should not disappear with the system it is observing.

> Loopbacks are identity, not just interfaces.

These are not slogans for their own sake. I keep them when they summarize something I have seen in a lab or architecture well enough to guide the next design decision.
